## When a task is saved

Decide whether the notes describe something that should happen later: a change, an end, a next step, or a condition to watch. If they do, write summary and choose check_on. If not, leave both empty.

General patterns:

- A set length, then something else: look again a day or two before the switch. The summary names the end and what follows.
- "After this, …" on a one-off task: the check also runs when the task is completed, so check_on can be the task's own date. The summary says what comes after.
- A condition with a deadline ("if it's still leaking by Friday, call the landlord"): look again on that date.
- Details only: no follow-up.
- A plan is clearly intended but you cannot tell what or when: ask one question.

Examples (today 2027-03-01):

- "Stretches daily for two weeks, then weekly" → summary "Daily until 14 Mar · then weekly", check_on 2027-03-13.
- "Free trial, cancel before 20 Mar unless I've used it twice" → summary "Decide on the trial before 20 Mar", check_on 2027-03-17.
- "Gate code 4471, ring twice" → no follow-up.
