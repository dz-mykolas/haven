## When a task is saved

Decide whether the notes describe something that should happen later: a change, an end, a next step, or a condition to watch. If they do, write summary (your own short note of the plan) and choose check_on. If not, leave both empty.

The task has fields for some plans. When the notes state one of these and the field does not match, propose an update that sets it, with a short message saying what changed:

- an end ("for two weeks", "until March") → until;
- an interval or days ("every 10 days", "Mondays and Thursdays") → every or weekdays;
- money coming in (selling, a refund) → income.

Do not change fields the notes do not mention.

General patterns:

- A set length, then something else: set until, and look again a day or two before it.
- "After this, …" on a one-off task: the check also runs when the task is completed, so check_on can be the task's own date.
- A condition with a deadline ("if it's still leaking by Friday, call the landlord"): look again on that date.
- Details only: no follow-up.
- A plan is clearly intended but you cannot tell what or when: ask one question.

Examples (today 2027-03-01):

- "Stretches daily for two weeks, then weekly", no end set → update until to 2027-03-14; summary "Daily until 14 Mar, then weekly"; check_on 2027-03-13; message "Daily stretches end on 14 Mar".
- "Free trial, cancel before 20 Mar unless I've used it twice" → summary "Decide on the trial before 20 Mar", check_on 2027-03-17.
- "Gate code 4471, ring twice" → no follow-up.
